

# Nextcloud + ONLYOFFICE on One VPS (No Docker, One Nginx)

**Target OS:** Ubuntu 24.04 LTS (arm64) — clean VPS with basic build tools.
**Architecture:** One public domain (`docs.<basedomain>`), one Nginx, TLS via Let’s Encrypt, **Nextcloud at `/`**, **ONLYOFFICE at `/onlyoffice/`**, internal localhost wiring.
**Packages:** Nextcloud from vendor tarball; ONLYOFFICE DocumentServer from vendor APT repo.
**No Snap. No Docker.**

> Why: Vendor tarball (Nextcloud) and upstream APT (ONLYOFFICE) keep you on supported update paths without container/webserver baggage. A single Nginx simplifies TLS, headers, uploads, and logging.

---

## 1) Inputs the admin must supply (scripts prompt for these)

* **Base domain** (e.g., `example.com`)
* **Deployment FQDN**: must be `docs.example.com`, present in DNS (A record to the VPS). (It’s fine if `example.com` and `www.example.com` also exist.)
* **Admin email** (Let’s Encrypt contact)

> Why: We **don’t** rely on a Cloudflare API token here; we assume DNS already points at the VPS. If DNS isn’t ready, scripts should stop and ask the admin to fix it.

---

## 2) Secrets & parameters the scripts must **generate** and **persist**

The scripts should **auto-generate** (random, high-entropy) values for:

* **MariaDB (Nextcloud) password:** `NC_DB_PASSWORD`
* **PostgreSQL (ONLYOFFICE) password:** `OO_DB_PASSWORD`
* **JWT secret shared by Nextcloud↔︎ONLYOFFICE:** `OO_JWT_SECRET`

And **write all parameters** (including user-supplied domain/email) to a **single parameters file**:

* **Path:** `/etc/nextcloud-onlyoffice/params.yaml`
* **Ownership/perm:** `root:root` and `0600`
* **Contract:** scripts **read from & update** this file; they **do not echo secrets** to the console.

**Example `params.yaml` (format stable for agents):**

```yaml
deployment:
  fqdn: "docs.example.com"
  admin_email: "admin@example.com"

nextcloud:
  db_name: "nextcloud"
  db_user: "ncuser"
  db_password: "REDACTED_AutoGenerated"
  data_dir: "/var/www/nextcloud/data"

onlyoffice:
  db_name: "onlyoffice"
  db_user: "onlyoffice"
  db_password: "REDACTED_AutoGenerated"
  jwt_secret: "REDACTED_AutoGenerated"
  listen_port: 8082

php:
  memory_limit: "512M"
  upload_max_filesize: "4G"
  post_max_size: "4G"
```

> Why: Agents need a **source of truth** across multiple runs. A root-only YAML keeps secrets centralized yet easy to parse.

**Acceptable secret generation pattern (for your scripts):**

* `openssl rand -hex 24` for DB passwords and JWT secret
* Or `/usr/bin/uuidgen | tr -d '-' | head -c 48`

## 4) Databases (create with generated passwords)

**Nextcloud (MariaDB):**

```bash
mysql -e "CREATE DATABASE nextcloud CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
mysql -e "CREATE USER 'ncuser'@'localhost' IDENTIFIED BY 'NC_DB_PASSWORD_PLACEHOLDER';"
mysql -e "GRANT ALL PRIVILEGES ON nextcloud.* TO 'ncuser'@'localhost'; FLUSH PRIVILEGES;"
```

**ONLYOFFICE (PostgreSQL):**

```bash
sudo -i -u postgres psql -c "CREATE DATABASE onlyoffice;"
sudo -i -u postgres psql -c "CREATE USER onlyoffice WITH PASSWORD 'OO_DB_PASSWORD_PLACEHOLDER';"
sudo -i -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE onlyoffice TO onlyoffice;"
```

(Passwords are substituted from `params.yaml` at runtime.)&#x20;

**Enable Redis (lock cache) now:** `systemctl enable --now redis-server`

## 5) Nextcloud (vendor tarball)

```bash
cd /var/www
curl -LO https://download.nextcloud.com/server/releases/latest.tar.bz2
tar -xjf latest.tar.bz2
chown -R www-data:www-data /var/www/nextcloud
```

**PHP-FPM tuning** (`/etc/php/8.3/fpm/php.ini`):

```ini
memory_limit = 512M
upload_max_filesize = 4G
post_max_size = 4G
max_execution_time = 3600
opcache.enable=1
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=10000
opcache.memory_consumption=128
opcache.save_comments=1
```

`systemctl restart php8.3-fpm`

> Why: Nextcloud recommends APCu + Redis and sane upload/opcache limits for performance.

## 6) ONLYOFFICE DocumentServer (vendor APT)

```bash
curl -fsSL https://download.onlyoffice.com/repo/onlyoffice.key | gpg --dearmor -o /usr/share/keyrings/onlyoffice.gpg
echo 'deb [signed-by=/usr/share/keyrings/onlyoffice.gpg] https://download.onlyoffice.com/repo/debian squeeze main' \
  > /etc/apt/sources.list.d/onlyoffice.list

apt update
DEBIAN_FRONTEND=noninteractive apt -y install onlyoffice-documentserver
```

During installation, the package may prompt for PostgreSQL credentials; precreating them (above) and/or preseeded debconf avoids surprises. The Canonical walkthrough confirms **PostgreSQL + RabbitMQ** as required components and shows DS repo install flow. &#x20;

**Bind DS to localhost** (avoid public exposure) in `/etc/onlyoffice/documentserver/local.json`:

```json
"services": {
  "CoAuthoring": {
    "server": {
      "port": 8082,
      "bind_address": "127.0.0.1"
    }
  }
}
```

`systemctl restart onlyoffice-documentserver`

> Why: We front DS with our own Nginx, so DS should listen on 127.0.0.1 only.

## 8) Single Nginx vhost (Nextcloud `/`, ONLYOFFICE `/onlyoffice/`)

`/etc/nginx/conf.d/nextcloud.conf`:

```nginx
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
  listen 80;
  server_name docs.example.com;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl http2;
  server_name docs.example.com;

  ssl_certificate     /etc/letsencrypt/live/docs.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/docs.example.com/privkey.pem;

  root /var/www/nextcloud;
  index index.php;
  client_max_body_size 0;

  # Nextcloud app
  location / { try_files $uri $uri/ /index.php$request_uri; }

  # PHP-FPM
  location ~ \.php$ {
    include fastcgi_params;
    fastcgi_split_path_info ^(.+\.php)(/.+)$;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_param PATH_INFO $fastcgi_path_info;
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    fastcgi_intercept_errors on;
    fastcgi_request_buffering off;
    fastcgi_read_timeout 3600;
  }

  # ONLYOFFICE under /onlyoffice/
  location ^~ /onlyoffice/ {
    proxy_pass         http://127.0.0.1:8082/;   # NOTE trailing slash
    proxy_http_version 1.1;

    # make DS generate subpath-correct URLs:
    proxy_set_header   X-Forwarded-Host  $host/onlyoffice;

    # standard proxy + websockets:
    proxy_set_header   Host              $host;
    proxy_set_header   X-Forwarded-Proto https;
    proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header   Upgrade           $http_upgrade;
    proxy_set_header   Connection        $connection_upgrade;

    client_max_body_size 0;
    proxy_read_timeout 3600;
    proxy_send_timeout 3600;
    proxy_buffering off;
    proxy_redirect off;
  }
}
```

`nginx -t && systemctl reload nginx`

> Why: Subpath deployments need the trailing slash on `proxy_pass` and the `X-Forwarded-Host $host/onlyoffice` hint so DS constructs correct callback/editor URLs.

## 9) Nextcloud `config.php` (script writes these)

`/var/www/nextcloud/config/config.php` additions:

```php
'trusted_domains' => ['docs.example.com'],
'overwrite.cli.url' => 'https://docs.example.com',

'dbtype' => 'mysql',
'dbname' => 'nextcloud',
'dbuser' => 'ncuser',
'dbpassword' => 'NC_DB_PASSWORD_PLACEHOLDER',
'dbhost' => 'localhost',

'memcache.local'   => '\OC\Memcache\APCu',
'memcache.locking' => '\OC\Memcache\Redis',
'redis' => ['host' => '127.0.0.1', 'port' => 6379],

'allow_local_remote_servers' => true
```

> Why: `allow_local_remote_servers` lets Nextcloud safely talk to services on 127.0.0.1 (e.g., DS).

## 10) Wire ONLYOFFICE (via `occ`)

```bash
sudo -u www-data php /var/www/nextcloud/occ app:install onlyoffice || true
sudo -u www-data php /var/www/nextcloud/occ app:enable onlyoffice

# public editor URL (must be HTTPS on your domain)
sudo -u www-data php /var/www/nextcloud/occ \
  config:app:set onlyoffice DocumentServerUrl --value="https://docs.example.com/onlyoffice/"

# internal service URLs (localhost)
sudo -u www-data php /var/www/nextcloud/occ \
  config:app:set onlyoffice DocumentServerInternalUrl --value="http://127.0.0.1:8082/"

sudo -u www-data php /var/www/nextcloud/occ \
  config:app:set onlyoffice StorageUrl --value="http://127.0.0.1/"

# shared JWT secret
sudo -u www-data php /var/www/nextcloud/occ \
  config:app:set onlyoffice jwt_secret --value="OO_JWT_SECRET_PLACEHOLDER"
```

> Why: Public URL stays HTTPS (fronted by Nginx), while internal URLs are plain HTTP on localhost for simplicity and speed.


4. **Manual functional test**
   Upload a `.docx` to Nextcloud and open it in the web UI; ensure the editor loads and co-authoring works (websockets).

## 13) Agent notes (Augment or Cursor)

* Treat `/etc/nextcloud-onlyoffice/params.yaml` as the **authoritative parameters source**.
* When scripts **create** secrets (DB passwords / JWT), they **must update** this file.
* When scripts change PHP limits, DS port, or FQDN, they **must update** this file.
* Do **not** print secrets to stdout or logs; show masked values if needed.
* Keep `/var/www/nextcloud/config/config.php` and Nginx in sync with `params.yaml`.
